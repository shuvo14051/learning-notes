Object-Oriented Programming

Advanced Properties, Invariants, and __slots__

Control reading, assignment, and deletion; preserve valid object state; and understand when fixed attribute storage is useful.

August 22, 2026 • Ahamed Learning Notes

Encapsulation is not only about creating classes or hiding names. A well-designed object controls the operations that can change its state and keeps its rules true throughout its lifetime.

Python supports this design through:

  • property getters, setters, and deleters
  • validation and object invariants
  • clear choices between properties and methods
  • __slots__ for fixed instance storage

01 — Managed attributes

Properties hide logic behind attribute syntax

A normal public attribute is simply stored state:

class Person:
    def __init__(self, age):
        self.age = age


person = Person(25)
print(person.age)  # 25

If the class later needs validation or computation, changing callers from person.age to person.get_age() would alter the public interface. A property adds behavior while preserving attribute syntax. 

class Person:
    def __init__(self, age):
        self._age = age

    @property
    def age(self):
        return self._age


person = Person(30)
print(person.age)  # 30
A property is descriptor-managed behavior presented through an attribute-like interface.

02 — Controlled assignment

Property setters validate changes

A setter intercepts assignment to the public property name. The class can validate the new value before changing its internal state. 

class Person:
    def __init__(self, age):
        self.age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if isinstance(value, bool) or not isinstance(value, int):
            raise TypeError("age must be an integer")

        if value < 0:
            raise ValueError("age cannot be negative")

        self._age = value

Notice that __init__ assigns through self.age, not directly through self._age. Initial and later values therefore follow the same rules. 

person = Person(25)
print(person.age)  # 25

person.age = 40
print(person.age)  # 40

person.age = -10
# ValueError: age cannot be negative

Writing person.age = 40 invokes the method decorated with @age.setter. The valid value is then stored in the backing attribute _age.

03 — Controlled deletion

Property deleters define what del means

A deleter runs when callers delete the public property. It can remove storage, replace the value, release another resource, or reject deletion entirely. 

class User:
    def __init__(self, password):
        self._password = password

    @property
    def password(self):
        return self._password

    @password.deleter
    def password(self):
        print("Password removed")
        self._password = None


user = User("secret123")
print(user.password)

del user.password
print(user.password)
secret123
Password removed
None

The statement del user.password invokes the method decorated with @password.deleter. This example clears the value rather than removing _password completely.

Deletion can be forbidden

class User:
    def __init__(self, username):
        self._username = username

    @property
    def username(self):
        return self._username

    @username.deleter
    def username(self):
        raise AttributeError("username cannot be deleted")
Add a deleter only when deletion has a meaningful domain behavior. Most properties do not need one.

04 — Valid state

Validation protects invariants

An invariant is a condition that must remain true for an object to be considered valid. Examples include:

  • age must not be negative
  • an account balance must follow the account's overdraft rules
  • temperature cannot be below absolute zero

Every route that changes relevant state must preserve the invariant—including object construction. 

class BankAccount:
    def __init__(self, balance=0):
        self.balance = balance

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if not isinstance(value, (int, float)):
            raise TypeError("balance must be numeric")

        if value < 0:
            raise ValueError("balance cannot be negative")

        self._balance = value


account = BankAccount(1000)
account.balance = 2000

print(account.balance)  # 2000

account.balance = -500
# ValueError: balance cannot be negative

This property prevents invalid assignment through balance. In a richer banking model, deposits and withdrawals would usually be methods because they represent domain actions and may need additional rules or records.

Validation is complete only when every supported mutation path preserves the same invariant.

05 — API design

Choose between a property and a method

A property should conceptually behave like information about an object. A method should represent an action or potentially substantial operation.

Use a property when... Use a method when...
The result feels like data The operation feels like an action
Access is inexpensive and unsurprising Work may be slow, fail, or have visible effects
No call arguments are needed The operation needs arguments
Examples: area, age, balance Examples: deposit(), save(), train()

A derived value works naturally as a property

import math


class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return math.pi * self.radius**2


circle = Circle(5)
print(circle.area)
78.53981633974483

Area behaves like information about the circle, so circle.area is intuitive.

A state-changing action works naturally as a method

class BankAccount:
    def __init__(self, balance):
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("deposit must be positive")

        self.balance += amount


account = BankAccount(500)
account.deposit(200)

print(account.balance)  # 700
A useful shorthand is “properties are nouns; methods are verbs,” but cost and side effects matter too. Expensive or surprising work should be visible as a method call.

06 — Instance storage

Normal objects usually have a dictionary

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age


person = Person("Alice", 30)
print(person.__dict__)
{'name': 'Alice', 'age': 30}

An instance dictionary provides flexibility. New attributes can be added at runtime: 

person.height = 170
print(person.__dict__)
{'name': 'Alice', 'age': 30, 'height': 170}

That flexibility has a memory cost because each instance needs storage for its attribute mapping.

07 — Fixed storage

Use __slots__ to declare instance attributes

__slots__ lets a class declare a fixed set of instance attribute names. Instances can store those attributes without a normal per-instance __dict__, unless a dictionary is provided by the class hierarchy or explicitly included in the slots. 

class Person:
    __slots__ = ("name", "age")

    def __init__(self, name, age):
        self.name = name
        self.age = age


person = Person("Bob", 40)

print(person.name)  # Bob
print(person.age)   # 40
print(hasattr(person, "__dict__"))  # False

An undeclared attribute cannot be added:

person.height = 180
# AttributeError: 'Person' object has no attribute 'height'

The restriction also catches misspelled attribute assignments that would otherwise silently create a new instance attribute.

08 — Combine the tools

Properties work with slotted storage

A slot can hold a property's backing value just as an instance dictionary would. 

class Person:
    __slots__ = ("name", "_age")

    def __init__(self, name, age):
        self.name = name
        self.age = age

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if isinstance(value, bool) or not isinstance(value, int):
            raise TypeError("age must be an integer")

        if value < 0:
            raise ValueError("age cannot be negative")

        self._age = value


person = Person("Ahamed", 30)
person.age = 31

print(person.age)  # 31

The slot is named _age because that is where the setter stores the validated value. The public name age belongs to the property on the class.

09 — Tradeoffs

When should you use __slots__?

Potential benefits

  • lower per-instance memory usage for many small objects
  • prevention of undeclared instance attributes
  • potential attribute-access improvements in some implementations

Costs and limitations

  • less flexibility for adding attributes dynamically
  • extra care around inheritance and multiple inheritance
  • weak references require a __weakref__ slot when needed
  • some tools expect objects to provide __dict__

__slots__ is most valuable when measurement shows that per-instance memory matters—for example, when creating a very large number of small, structurally identical objects.

Treat __slots__ as a storage and memory design tool, not as a security feature or a default requirement for every class.

10 — Summary

Key takeaways

  • A setter validates assignment to a property.
  • A deleter defines or rejects deletion behavior.
  • Every supported mutation path should preserve object invariants.
  • Properties represent data; methods usually represent actions.
  • __slots__ can reduce per-instance storage.
  • Slots trade dynamic flexibility for a fixed attribute layout.
Final idea: Encapsulation succeeds when an object's interface makes valid operations natural and invalid states difficult to create.
