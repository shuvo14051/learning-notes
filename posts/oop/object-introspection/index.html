Python Object Introspection

Look inside Python objects at runtime using __dict__, vars(), dir(), getattr(), and setattr().

August 16, 2026 • Ahamed Learning Notes

Everything in Python is an object, and introspection lets a program examine those objects while it is running. You can discover attributes, read them by name, update them dynamically, and use that behavior to build tools such as serializers, configuration loaders, debuggers, and frameworks.

Tool Main question Result
__dict__ What is stored directly here? Attribute mapping
vars() Can I retrieve that namespace cleanly? Attribute or local mapping
dir() Which attribute names are discoverable? Sorted list of names
getattr() What is the value of this name? Attribute value
setattr() Can I assign this name dynamically? Updates the object

01 — Direct storage

__dict__: where ordinary attributes live

Most user-defined objects store their instance attributes in a dictionary exposed as __dict__. 

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age


person = Person("Ahamed", 30)
print(person.__dict__)
{'name': 'Ahamed', 'age': 30}

The keys are attribute names and the values are the objects stored under those names. Directly changing this dictionary changes the corresponding ordinary instance attribute: 

person.__dict__["age"] = 31
print(person.age)  # 31

Direct dictionary mutation is useful for understanding storage, but normal application code should usually prefer setattr(). It respects custom attribute-assignment behavior and descriptors.

Classes have dictionaries too

print(Person.__dict__)

A class namespace contains functions, class attributes, and other class-level definitions. Person.__dict__ is exposed as a read-only mappingproxy, so class attributes should be changed through assignment or setattr(): 

setattr(Person, "species", "human")
print(Person.species)  # human
Instance attributes commonly live in instance.__dict__. Class definitions live in the namespace represented by Class.__dict__.

Not every object has a __dict__

Built-in types and classes using __slots__ may store state without an instance dictionary. 

class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y


point = Point(2, 3)
print(point.x)
print(point.__dict__)  # AttributeError

02 — Namespace helper

vars(): a clean interface to a namespace

With an object argument, vars(object) returns that object's __dict__ when one exists. 

print(vars(person))
print(vars(person) is person.__dict__)
{'name': 'Ahamed', 'age': 31}
True

Because this is the actual dictionary rather than a copy, changes made through the returned mapping affect the instance. 

attributes = vars(person)
attributes["name"] = "Sara"

print(person.name)  # Sara

If an object does not provide __dict__, passing it to vars() raises TypeError.

vars() without an argument

Inside a function, calling vars() without an argument returns the current local namespace mapping, like locals(). 

def inspect_locals():
    language = "Python"
    level = "OOP"
    return vars()


print(inspect_locals())
# {'language': 'Python', 'level': 'OOP'}

03 — Name discovery

dir(): what names are discoverable?

While __dict__ shows one object's direct storage, dir() returns a sorted list of attribute names associated with an object. 

names = dir(person)

print("name" in names)       # True
print("__class__" in names)  # True

The result commonly includes:

  • instance attribute names
  • class attribute and method names
  • inherited names
  • special methods such as __str__

This makes dir() useful for interactive exploration, debugging, and autocomplete-like tools.

dir() is a discovery aid, not a guaranteed complete map of everything an object could return dynamically. A custom __dir__ can change the list, and __getattr__ may produce names that are not listed.

04 — Dynamic reading

getattr(): read an attribute by name

Normal attribute syntax places the name directly in the code:

print(person.name)

getattr() accepts the attribute name as a string: 

print(getattr(person, "name"))

This matters when the name comes from data, configuration, or user input rather than being known when the program is written. 

field = "age"
print(getattr(person, field))  # 31

Provide a default for a missing attribute

print(getattr(person, "height", None))  # None

Without a default, a missing name raises AttributeError. With a default, getattr() returns that value instead. 

sentinel = object()
value = getattr(person, "height", sentinel)

if value is sentinel:
    print("height is missing")

A unique sentinel distinguishes a missing attribute from an attribute whose real value is None.

getattr(obj, name) uses normal attribute lookup. That means properties, descriptors, inheritance, and __getattr__ still participate.

05 — Dynamic writing

setattr(): assign an attribute by name

setattr() is the dynamic equivalent of ordinary attribute assignment. 

setattr(person, "age", 40)
print(person.age)  # 40

The name and value can both come from variables:

field = "age"
value = 50

setattr(person, field, value)
print(person.age)  # 50

Just like obj.name = value, setattr() goes through Python's attribute-assignment machinery. A property setter, another data descriptor, or a custom __setattr__ can validate or reject the assignment. 

class Account:
    def __init__(self):
        self._balance = 0

    @property
    def balance(self):
        return self._balance

    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("balance cannot be negative")
        self._balance = value


account = Account()
setattr(account, "balance", 100)
print(account.balance)  # 100
Prefer setattr() over writing directly to __dict__ when you want normal assignment rules to run.

06 — Put it together

Load dynamic data into an object

A small configuration loader shows how introspection tools work together: 

class Settings:
    allowed_fields = {"theme", "language", "page_size"}

    def __init__(self):
        self.theme = "light"
        self.language = "en"
        self.page_size = 20

    def update(self, values):
        for name, value in values.items():
            if name not in self.allowed_fields:
                raise ValueError(f"unknown setting: {name}")

            setattr(self, name, value)

    def as_dict(self):
        return vars(self).copy()


settings = Settings()
settings.update({"theme": "dark", "page_size": 50})

print(getattr(settings, "theme"))
print(settings.as_dict())
dark
{'theme': 'dark', 'language': 'en', 'page_size': 50}

Real systems should validate external field names and values before assigning them. Dynamic access is powerful, but accepting every arbitrary attribute can hide mistakes or expose internal state.

07 — Summary

Choose the tool by the question

  • Use __dict__ to inspect direct namespace storage when the object provides it.
  • Use vars() for a convenient namespace mapping.
  • Use dir() to discover likely attribute names.
  • Use getattr() to read a name dynamically.
  • Use setattr() to assign a name dynamically.
Introspection is not a separate trick layered on top of Python's object model. It exposes the same namespaces and lookup rules that normal attribute syntax uses every day.
