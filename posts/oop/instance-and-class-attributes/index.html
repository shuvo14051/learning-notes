Instance and Class Attributes in Python

Move beyond the blueprint analogy and understand where Python stores object state, shared behavior, and class-level defaults.

August 27, 2026 • Ahamed Learning Notes

Beginner tutorials often say, “A class is a blueprint, and an object is built from that blueprint.” The analogy is useful, but it hides the mechanics that explain where attributes live, why self exists, and how instances share class behavior.

Let’s replace the analogy with a more precise mental model.

1. The core model

For an ordinary Python class:

  1. The class normally stores shared behavior and class-level attributes.
  2. Each instance normally stores its own state and has its own identity.
  3. Functions defined in the class body are stored once on the class and shared by its instances.
Mental model: The instance stores individual state. The class supplies shared behavior and shared defaults.

2. Inspect what an instance stores

class Dog:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return self.name + " says woof"


d = Dog("Fido")

The assignment self.name = name creates an attribute on the new instance. For a typical class with an instance dictionary, we can inspect that state using __dict__: 

print(d.__dict__)

The result is:

{'name': 'Fido'}

The instance dictionary contains name, but it does not contain speak. The function was defined in the class body, so it lives in the class dictionary: 

print(Dog.__dict__["speak"])

This displays a function object similar to:

<function Dog.speak at 0x...>
The Dog class stores one speak function. Every Dog instance can use that shared function with its own instance data.

3. What happens during a method call?

Consider this call:

d.speak()

For this ordinary instance method, it has the same effect as:

Dog.speak(d)

This works because:

  • Dog.speak accesses the function through the class.
  • The function expects an instance as its first argument.
  • d.speak creates a bound method that supplies d.

Calling the function through the class without an instance fails:

Dog.speak()  # TypeError: the required self argument is missing

This connection between a class function and an instance is explored in detail in the bound-method note.

4. Instance attributes hold individual data

The expression Dog.name fails in this example because no name attribute was assigned to the class. The name is created separately on each instance inside __init__. 

d1 = Dog("Fido")
d2 = Dog("Buddy")

print(d1.name)  # Fido
print(d2.name)  # Buddy

There are two objects, two separate name attributes, and one shared speak function on the class.

5. Instance attributes versus class attributes

Instance attribute

An instance attribute is assigned through an instance—usually through self inside __init__. Each object can hold a different value. 

class Car:
    def __init__(self, brand):
        self.brand = brand

Each Car instance can have its own brand.

Class attribute

A class attribute is assigned in the class body and is available through the class and its instances. 

class Car:
    wheels = 4

    def __init__(self, brand):
        self.brand = brand
c1 = Car("Toyota")
c2 = Car("Honda")

print(c1.wheels)  # 4
print(c2.wheels)  # 4
print(Car.wheels) # 4

Neither instance needs its own wheels attribute. Both find the shared value on Car.

6. Attribute lookup and inheritance

For a simple attribute such as the integer Car.wheels, evaluating c1.wheels can be understood with this lookup path:

  1. Look for wheels on c1.
  2. Look on Car.
  3. Continue through the parent classes according to the method resolution order.

Python's complete lookup rules also account for descriptors, but this model accurately explains ordinary instance and class data. 

print(c1.__dict__)       # {'brand': 'Toyota'}
print(Car.__dict__["wheels"])  # 4

Because c1 has no wheels attribute of its own, lookup continues to the class and returns Car.wheels.

7. An instance attribute can shadow a class attribute

Now assign a value through one instance:

c1.wheels = 6

print(c1.wheels)  # 6
print(c2.wheels)  # 4
print(Car.wheels) # 4

The assignment creates a new wheels entry in c1.__dict__. It does not update Car.wheels. 

print(c1.__dict__)
# {'brand': 'Toyota', 'wheels': 6}

print(c2.__dict__)
# {'brand': 'Honda'}

Lookup finds c1.wheels before it needs the class value, so the instance attribute shadows the class attribute. The other instance still falls back to the class.

Shadowing does not overwrite the class attribute. It gives one instance an attribute with the same name, hiding the class value for lookups through that instance.

8. Change the class attribute itself

To update the shared value, assign through the class:

Car.wheels = 8

print(c1.wheels)  # 6
print(c2.wheels)  # 8
print(Car.wheels) # 8
  • c2 has no instance-level wheels, so it sees the updated class value.
  • c1 still has its own wheels, so its value remains 6.

Deleting the shadowing attribute would make c1 fall back to the class again: 

del c1.wheels
print(c1.wheels)  # 8

9. Be careful with mutable class attributes

Class attributes are shared. That is useful for constants and defaults, but it can surprise you when the shared object is mutable. 

class Team:
    members = []


team_a = Team()
team_b = Team()

team_a.members.append("Ahamed")
print(team_b.members)  # ['Ahamed']

Both instances find the same list on the class. If each instance should have its own list, create it in __init__: 

class Team:
    def __init__(self):
        self.members = []
Put shared values on the class. Put independently mutable state on each instance.

Summary

  • Class: shared behavior and shared defaults.
  • Instance: individual state and identity.
  • Attribute access: finds an instance value when present, otherwise it can fall back to the class hierarchy.
  • Shadowing: an instance attribute hides a class attribute of the same name for that instance.
Understanding where attributes are stored turns many surprising OOP behaviors into predictable lookup rules.
