Object-Oriented Programming

Python Object Model: The Ground Truth

Understand names, identity, mutability, copying, and argument passing—the mechanics that make Python's object-oriented behavior predictable.

August 25, 2026 • Ahamed Learning Notes

If you understand Python's object model, object-oriented programming stops feeling magical and starts feeling mechanical. The central idea is simple: Python works with objects, and names refer to those objects.

1. Everything is an object

In Python, everything you interact with is an object:

  • integers, strings, and lists
  • functions and classes
  • modules and class instances

When you write:

x = 10

Python creates—or reuses—an integer object and binds the name x to that object. The name is not the value itself; it is a reference to an object.

Remember: Names are labels. Objects exist independently of the names that currently refer to them.

2. Functions are first-class objects

A first-class object can be assigned to a name, passed as an argument, returned from another function, or stored in a data structure. Python functions support all of these operations. 

def greet():
    return "hello"


a = greet
b = greet

print(a())
print(a is b)

Calling a() works because a refers to the function object. Both a and b refer to that same object, so a is b is True.

Key idea: A function definition creates a function object and binds its name to that object.

3. Identity versus equality

Every Python object has an identity, a type, and a value.

a = [1, 2]
b = [1, 2]

print(a == b)  # True
print(a is b)  # False

The == operator checks whether two objects have equal values. The is operator checks whether two references point to the exact same object.

Rule of thumb: Use == for value comparison. Use is for identity checks, especially checks such as value is None.

4. Mutability versus immutability

A mutable object can change while keeping the same identity. A list is mutable, so append() changes the existing list object. 

a = [1, 2]
print(id(a))

a.append(3)
print(id(a))

Immutable objects cannot be changed in place. Integers are immutable, so x += 1 calculates a new integer and rebinds x to it. 

x = 10
print(id(x))

x += 1
print(id(x))
Mutation changes an existing object. Rebinding makes a name refer to a different object.

5. Assignment does not copy

a = [1, 2]
b = a

a.append(3)
print(b)  # [1, 2, 3]

The assignment b = a does not create another list. It binds b to the same list as a. A mutation made through either name is therefore visible through both names.

6. Shallow copy versus deep copy

Nested mutable objects make copying more important.

import copy

a = [[1], [2]]
b = a
c = a.copy()
d = copy.deepcopy(a)

a[0].append(99)

print(b)  # [[1, 99], [2]]
print(c)  # [[1, 99], [2]]
print(d)  # [[1], [2]]
  • b refers to the same outer list as a.
  • c is a new outer list, but it shares the original inner lists.
  • d is a deep copy with recursively copied inner lists.
Shallow copy: copy the container but share its nested objects. Deep copy: recursively copy the complete object graph when possible.

7. Passing objects to functions

Python passes objects by assignment. A function parameter becomes a new local name referring to the object supplied by the caller. If the function mutates that object, the caller can observe the change. 

def modify(items):
    items.append(10)


data = []
modify(data)
print(data)  # [10]

Rebinding the local parameter is different. It changes only what the local name refers to; it does not rebind the caller's name. 

def reassign(items):
    items = [100]


data = []
reassign(data)
print(data)  # []
Key distinction: Mutating the shared object can affect the caller. Rebinding a local parameter does not.

8. The nested mutability trap

a = (1, 2, [3])
b = a

a[2].append(4)

print(a)  # (1, 2, [3, 4])
print(b)  # (1, 2, [3, 4])

A tuple is immutable: its references cannot be replaced. However, the tuple can refer to a mutable list, and that list can still be changed. Both names reveal the mutation because they refer to the same tuple containing the same list.

Remember: An immutable container does not make every object inside it immutable.

Important interview questions

What is the difference between == and is?

== compares values; is compares object identity.

Why do these two examples behave differently?

a = [1, 2]
b = a
a += [3]

x = 10
y = x
x += 1

A list's in-place addition mutates the list, so b sees the change. An integer cannot be mutated, so adding one creates a new integer and rebinds x; y still refers to the original integer.

What does this shallow-copy example print?

a = [[1], [2]]
b = a.copy()
a[0].append(5)
print(b)

It prints [[1, 5], [2]] because the shallow copy shares the inner lists.

What does “functions are first-class objects” mean?

Functions can be assigned, passed, returned, and stored just like other Python objects.

What happens when a function name is rebound?

def f():
    return 1


g = f
f = 10

print(g())  # 1

Rebinding f does not change the function object or the existing reference stored in g.

How does Python pass arguments?

Parameters are local names bound to the supplied objects. Mutating a shared object may affect the caller, while rebinding a parameter affects only the local name.

The ground truth: Names refer to objects. Assignment binds names, mutation changes objects, and identity tells you whether two references lead to the same object.
