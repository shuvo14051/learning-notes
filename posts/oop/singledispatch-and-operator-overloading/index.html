Object-Oriented Programming

singledispatch and Operator Overloading

Extend Python behavior by dispatching on types and teaching custom objects how to participate in operators and built-in protocols.

September 3, 2026 • Ahamed Learning Notes

Flexible arguments and method overriding cover many polymorphic designs. Python also provides two more explicit mechanisms: singledispatch selects a function implementation by type, while special methods define how objects interact with operators and built-in functions.

01 — Generic functions

Dispatch on the first argument's type

functools.singledispatch turns one function into a generic function with a registry of type-specific implementations. 

from functools import singledispatch


@singledispatch
def process(value):
    return f"default: {value}"


@process.register
def _(value: int):
    return f"int: {value * 2}"


@process.register
def _(value: str):
    return f"str: {value.upper()}"


print(process(10))
print(process("hello"))
print(process(3.14))
int: 20
str: HELLO
default: 3.14

The decorated base function is the fallback. Registered implementations handle selected types. Dispatch always uses the type of the first argument passed to the generic function.

singledispatch is runtime single dispatch—not traditional signature-based overloading. It does not select an implementation from every argument's combined types.

02 — Selection

How the dispatch registry works

A generic function maintains mappings from types to functions:

object → default implementation
int    → integer implementation
str    → string implementation

When process(value) runs:

  1. Python examines type(value).
  2. The dispatcher finds the most specific registered compatible type.
  3. That implementation receives the original arguments.
  4. If no specialized type matches, the base implementation runs.

The registry and selection can be inspected:

print(process.registry)
print(process.dispatch(int))
print(process.dispatch(float))

dispatch(int) returns the registered integer handler. With no float handler, dispatch(float) returns the fallback registered for object.

03 — Extensibility

Register behavior from another module

Code can add support for a new type without editing the module that defined the generic function.

core.py

from functools import singledispatch


@singledispatch
def process(value):
    return f"default: {value}"


@process.register
def _(value: int):
    return f"int: {value * 2}"

plugin.py

from core import process


@process.register
def _(value: list):
    return f"list length: {len(value)}"

main.py

import core
import plugin  # Runs the registration


print(core.process(10))
print(core.process([1, 2, 3, 4]))
print(core.process("hello"))
int: 20
list length: 4
default: hello

Importing plugin executes its decorator and updates the shared registry. The core source remains unchanged.

04 — Type hierarchy

Dispatch understands inheritance

from functools import singledispatch


class Shape:
    def area(self):
        raise NotImplementedError


class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height


class Square(Rectangle):
    def __init__(self, side):
        super().__init__(side, side)


@singledispatch
def describe(value):
    return "Unknown object"


@describe.register
def _(shape: Shape):
    return f"Shape with area {shape.area()}"


print(describe(Rectangle(4, 5)))
print(describe(Square(3)))
Shape with area 20
Shape with area 9

No handlers are registered specifically for Rectangle or Square. Their MROs contain Shape, so the registered Shape handler is compatible.

If a Rectangle handler were added, it would be more specific than Shape for both rectangle and square objects.

05 — Generic methods

Use singledispatchmethod inside a class

Ordinary singledispatch would see self as the first argument of an instance method. The singledispatchmethod decorator instead dispatches on the first non-self, non-cls argument. 

from functools import singledispatchmethod


class Processor:
    @singledispatchmethod
    def process(self, value):
        return f"default: {value}"

    @process.register
    def _(self, value: int):
        return f"int: {value * 2}"

    @process.register
    def _(self, value: str):
        return f"str: {value.upper()}"


processor = Processor()

print(processor.process(10))
print(processor.process("hello"))
print(processor.process(3.14))
int: 20
str: HELLO
default: 3.14

06 — Design choice

When is single dispatch useful?

It fits when:

  • behavior belongs to an external operation rather than the input class
  • you cannot or should not modify the input types
  • new type handlers should be registered independently
  • the first argument's type is enough to select behavior

Prefer an ordinary polymorphic method when the behavior naturally belongs to the object itself. Prefer simple branching when there are only one or two clear cases and a registry would add ceremony.

07 — Python protocols

Operator overloading maps syntax to special methods

Operator overloading defines what operators and built-in functions mean for a custom class. Python already uses this model for its built-in types: 

print(5 + 3)       # Numeric addition
print("a" + "b")   # String concatenation

Common mappings include:

Syntax Primary special method Purpose
a + ba.__add__(b)Add or combine
a - ba.__sub__(b)Subtract
a * ba.__mul__(b)Multiply
a / ba.__truediv__(b)True division
a == ba.__eq__(b)Value equality
a < ba.__lt__(b)Ordering
len(a)a.__len__()Length
str(a)a.__str__()Human-readable text

This syntax is conceptual: Python's data model controls the full dispatch procedure, including subclass priority and reflected methods. You normally implement special methods rather than call them directly.

08 — Addition

Teach a vector how to use +

class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented

        return Vector(self.x + other.x, self.y + other.y)

    def __str__(self):
        return f"({self.x}, {self.y})"


vector_1 = Vector(2, 3)
vector_2 = Vector(4, 5)

print(vector_1 + vector_2)
(6, 8)

The addition creates a new vector rather than mutating either operand. Returning NotImplemented for another type allows Python to try the reflected operation before ultimately raising TypeError.

Inside binary special methods, return NotImplemented for unsupported operand types. Do not raise NotImplementedError; the two values have different purposes.

09 — Equality

Define value comparison with __eq__

Without a custom equality method, ordinary user-defined objects do not compare equal merely because their attributes contain the same values. 

class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented

        return self.x == other.x and self.y == other.y


vector_1 = Vector(2, 3)
vector_2 = Vector(2, 3)

print(vector_1 == vector_2)  # True

The method defines logical equality from the values that matter to the class. Returning NotImplemented for unrelated types gives the other operand a chance to participate.

Defining equality can affect hashing behavior. Mutable value objects are generally not safe dictionary keys unless the class deliberately defines a consistent __hash__ policy.

10 — Reflected operations

Support both vector * 3 and 3 * vector

from numbers import Real


class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __mul__(self, scalar):
        if not isinstance(scalar, Real):
            return NotImplemented

        return Vector(self.x * scalar, self.y * scalar)

    def __rmul__(self, scalar):
        return self * scalar

    def __str__(self):
        return f"({self.x}, {self.y})"


vector = Vector(2, 3)

print(vector * 3)
print(3 * vector)
(6, 9)
(6, 9)

For vector * 3, Python uses Vector.__mul__. For 3 * vector, integer multiplication cannot handle the vector, so Python can try Vector.__rmul__ as the reflected operation.

11 — Design rules

Overload only when the meaning is natural

Operator overloading works well for:

  • mathematical objects such as vectors and matrices
  • custom containers participating in familiar protocols
  • domain values where comparison or combination is obvious
  • APIs that become clearer through standard Python syntax

A good overload should:

  • match the operator's conventional meaning
  • behave consistently with related operations
  • avoid surprising side effects
  • return NotImplemented for unsupported operands
If + naturally means add, concatenate, combine, or merge, it may improve the API. If it performs an unrelated action, give that action a descriptive method name.

12 — Practice

Build a ComplexNumber class

Create a class that supports:

  • + for complex-number addition
  • * for complex-number multiplication
  • == for value comparison
  • readable text such as 3 + 4i

Solution

class ComplexNumber:
    def __init__(self, real, imaginary):
        self.real = real
        self.imaginary = imaginary

    def __add__(self, other):
        if not isinstance(other, ComplexNumber):
            return NotImplemented

        return ComplexNumber(
            self.real + other.real,
            self.imaginary + other.imaginary,
        )

    def __mul__(self, other):
        if not isinstance(other, ComplexNumber):
            return NotImplemented

        real = self.real * other.real - self.imaginary * other.imaginary
        imaginary = self.real * other.imaginary + self.imaginary * other.real

        return ComplexNumber(real, imaginary)

    def __eq__(self, other):
        if not isinstance(other, ComplexNumber):
            return NotImplemented

        return (
            self.real == other.real
            and self.imaginary == other.imaginary
        )

    def __str__(self):
        sign = "+" if self.imaginary >= 0 else "-"
        return f"{self.real} {sign} {abs(self.imaginary)}i"


number_1 = ComplexNumber(3, 4)
number_2 = ComplexNumber(1, 2)

print(number_1 + number_2)
print(number_1 * number_2)
print(number_1 == ComplexNumber(3, 4))
4 + 6i
-5 + 10i
True

__add__ adds the real and imaginary components. __mul__ applies the complex multiplication formula. __eq__ compares logical values, and __str__ produces readable output.

13 — Summary

Two ways to extend behavior

  • singledispatch selects a function by first-argument type.
  • Registered ancestor types can handle subclass instances.
  • singledispatchmethod supports dispatch inside classes.
  • Special methods connect custom classes to Python syntax.
  • Reflected methods support reversed operand positions.
  • NotImplemented enables cooperative operator dispatch.
Final idea: Single dispatch extends an external operation by type. Operator overloading makes an object participate naturally in Python's existing data-model protocols.
