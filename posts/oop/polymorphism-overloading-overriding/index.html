Polymorphism: Overloading vs Overriding in Python

Separate flexible input handling from inherited behavior and see how Python expresses both forms of polymorphism.

September 1, 2026 • Ahamed Learning Notes

Polymorphism means that one interface can support multiple forms of behavior. Python embraces polymorphism, but it does not implement traditional signature-based method overloading like Java or C++.

Clean mental model: A Python name normally refers to one runtime function. That function can accept flexible inputs, or different classes can provide different implementations of the same operation.

01 — One interface, many forms

What is polymorphism?

Polymorphism allows the same operation to work across different values or objects. The caller uses a consistent interface while the behavior varies appropriately.

Common Python examples include:

  • len() working with strings, lists, tuples, and custom objects
  • + adding numbers or concatenating sequences
  • different classes implementing the same method name
  • one function accepting several useful argument forms
print(len("Python"))       # 6
print(len([10, 20, 30]))   # 3

The interface is len(value). Each object's type supplies the behavior that makes the operation meaningful.

02 — Traditional overloading

What method overloading means elsewhere

In languages with signature-based overloading, a class can define several methods with the same name but different parameter types or counts: 

add(a, b)
add(a, b, c)
add(a, b, c, d)

The language selects a matching implementation from the declared signatures. Python class and module namespaces do not retain several ordinary definitions under one name this way.

03 — Name rebinding

A later definition replaces the earlier binding

def greet(name):
    return f"Hello {name}"


def greet(name, message):
    return f"{message} {name}"


print(greet("Ahamed"))
# TypeError: greet() missing 1 required positional argument: 'message'

The second def creates another function and rebinds the name greet. The first function is no longer available through that name.

The same rule applies inside a class body:

class Greeter:
    def greet(self, name):
        return f"Hello {name}"

    def greet(self, name, message):
        return f"{message} {name}"


print(Greeter.__dict__["greet"])
# Only the second function is stored
Python does not select between these definitions by signature. The class namespace contains only the value assigned to greet last.

04 — Flexible signatures

Use default arguments for optional inputs

def greet(name, message="Hello"):
    return f"{message} {name}"


print(greet("Ahamed"))
print(greet("Ahamed", "Hi"))
Hello Ahamed
Hi Ahamed

One function supports both calls. If message is omitted, Python uses the default. If the caller supplies it, that argument replaces the default.

Defaults are the clearest choice when the forms differ only by a small number of optional parameters.

05 — Variable positional input

Use *args for any number of values

def add(*values):
    total = 0

    for value in values:
        total += value

    return total


print(add(1, 2))
print(add(1, 2, 3, 4))
3
10

Python collects extra positional arguments into a tuple. One implementation can therefore handle two, three, or many values.

For this particular example, the built-in sum() would be simpler, but *args is useful when the function has custom processing for a variable number of inputs.

06 — Variable named input

Use **kwargs for flexible named values

def describe(**fields):
    for name, value in fields.items():
        print(name, value)


describe(name="Ahamed", age=25)
name Ahamed
age 25

Extra keyword arguments become a dictionary. This can be useful for extensible settings, adapters, and forwarding arguments, but explicit named parameters are easier to document and validate when the supported fields are known.

07 — Combined inputs

Combine fixed and variable parameters carefully

def inspect_call(a, b=0, *args, **kwargs):
    print(a, b)
    print(args)
    print(kwargs)


inspect_call(1)
inspect_call(1, 2, 3, 4, x=10, y=20)
1 0
()
{}

1 2
(3, 4)
{'x': 10, 'y': 20}

The important binding sequence in this signature is:

required parameters → defaulted parameters → *args → **kwargs

Flexible signatures are powerful, but avoid using them when a small explicit signature would communicate the API more clearly.

08 — Input-based branching

One function can inspect its inputs

def combine(*values):
    if all(isinstance(value, (int, float)) for value in values):
        return sum(values)

    if all(isinstance(value, str) for value in values):
        return "".join(values)

    raise TypeError("values must be all numeric or all strings")


print(combine(5, 6))
print(combine("Hi ", "Ahamed"))
11
Hi Ahamed

This is still one function. It manually chooses behavior after inspecting the runtime values; it is not traditional method overloading.

Heavy chains of type checks can become difficult to extend. Often polymorphic methods or a dispatch tool provide a cleaner design.

09 — Runtime dispatch

Use singledispatch for type-based functions

The standard library's functools.singledispatch can select an implementation from the type of the first argument. 

from functools import singledispatch


@singledispatch
def serialize(value):
    raise TypeError(f"unsupported type: {type(value).__name__}")


@serialize.register
def _(value: int):
    return str(value)


@serialize.register
def _(value: list):
    return ",".join(str(item) for item in value)


print(serialize(42))
print(serialize([1, 2, 3]))
42
1,2,3

This is genuine runtime generic-function dispatch provided by a decorator, but it is different from retaining several normal function definitions under one name. Dispatch considers only the first argument's type.

10 — Static typing

typing.overload describes call signatures

Type checkers can understand several supported signatures through @overload. The overload declarations do not provide runtime implementations; one final function handles every call. 

from typing import overload


@overload
def double(value: int) -> int: ...


@overload
def double(value: str) -> str: ...


def double(value: int | str) -> int | str:
    return value * 2


print(double(4))     # 8
print(double("Hi"))  # HiHi
@overload helps static analysis and editor tooling. At runtime, only the final implementation is called.

11 — Inherited behavior

Method overriding changes behavior by object type

Overriding occurs when a child class defines its own version of an inherited method. 

class Animal:
    def speak(self):
        return "Some generic sound"


class Dog(Animal):
    def speak(self):
        return "Bark"


class Cat(Animal):
    def speak(self):
        return "Meow"


animals = [Animal(), Dog(), Cat()]

for animal in animals:
    print(animal.speak())
Some generic sound
Bark
Meow

The call expression remains animal.speak(). The actual object's class determines which method lookup finds. This is runtime polymorphism through overriding.

12 — Comparison

Overloading versus overriding

Feature Traditional overloading Overriding
Meaning Same name, different declared signatures Child replaces an inherited implementation
Relationship Usually within one class or scope Between ancestor and child classes
Normal Python support Not by repeated def declarations Directly supported
Behavior selected by Argument signature in languages that support it Runtime method lookup on the object
Python alternatives Defaults, *args, **kwargs, dispatch Define the method on a child class

13 — Side by side

Different inputs versus different classes

Overloading-style input flexibility

def area(length, width=None):
    if width is None:
        return length**2

    return length * width


print(area(5))
print(area(5, 3))
25
15

Overriding through separate types

class Shape:
    def area(self):
        raise NotImplementedError


class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side**2


class Rectangle(Shape):
    def __init__(self, length, width):
        self.length = length
        self.width = width

    def area(self):
        return self.length * self.width


print(Square(5).area())
print(Rectangle(5, 3).area())
25
15

The first example branches on the call shape inside one function. The second delegates the operation to the object's class.

14 — Summary

Key takeaways

  • Polymorphism means one interface can support many forms.
  • Repeated Python definitions rebind a name instead of creating overloads.
  • Defaults, *args, and **kwargs support flexible calls.
  • singledispatch provides first-argument runtime dispatch.
  • typing.overload describes signatures for type checkers.
  • Overriding provides object-dependent behavior through inheritance.
Final idea: Overloading is about accepting different input forms. Overriding is about different object types answering the same operation in their own way.
