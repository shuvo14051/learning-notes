Python Attribute Lookup Rules

Follow the real lookup order through data descriptors, instance attributes, class attributes, inheritance, and fallback behavior.

August 14, 2026 • Ahamed Learning Notes

Python attribute lookup can sound intimidating because it involves terms such as descriptors, __getattribute__, __getattr__, and the method resolution order. The behavior becomes predictable once you know the priority rules.

1. Where attributes are stored

The instance dictionary

Most ordinary Python objects store their instance attributes in obj.__dict__. Classes that use __slots__ may work differently. 

class Person:
    pass


person = Person()
person.name = "Ahamed"

print(person.__dict__)
# {'name': 'Ahamed'}

The class dictionary

A class has its own namespace, exposed as a read-only mapping by ClassName.__dict__. It contains class attributes, functions, properties, and other descriptors. 

class Person:
    species = "human"

    def greet(self):
        return "Hello"


print(Person.__dict__["species"])
print(Person.__dict__["greet"])

2. The two lookup hooks

__getattribute__: the gatekeeper

Every explicit instance attribute access goes through:

obj.__getattribute__("attribute_name")

In other words, evaluating obj.x invokes the attribute-lookup machinery implemented by __getattribute__. You can override it, but doing so affects every attribute access and can easily cause infinite recursion.

__getattr__: the fallback

__getattr__ is considered only after normal lookup fails with AttributeError. 

class Person:
    def __getattr__(self, name):
        return f"{name!r} was not found"


person = Person()
print(person.age)
# 'age' was not found
__getattribute__ handles every normal lookup. __getattr__ is the last-chance fallback when that lookup cannot produce an attribute.

3. The attribute lookup order

For an expression such as obj.x, remember this order:

  1. Search the object's class hierarchy for a data descriptor named x.
  2. Check the instance dictionary for x.
  3. Search the class hierarchy for a non-data descriptor or ordinary class attribute named x.
  4. If normal lookup raises AttributeError, use __getattr__ when it is defined.
Priority: data descriptor → instance dictionary → non-data descriptor or class attribute → __getattr__.

Searches of the class hierarchy follow the method resolution order (MRO), so inheritance is part of both class-level searches rather than a completely separate final step.

4. Data descriptors take priority

A descriptor is an object stored on a class that participates in attribute access. A descriptor defining __set__ or __delete__ in addition to __get__ is a data descriptor. Properties are the most familiar example. 

class Person:
    @property
    def name(self):
        return "Property Name"


person = Person()
person.__dict__["name"] = "Instance Name"

print(person.__dict__["name"])  # Instance Name
print(person.name)              # Property Name

The instance dictionary really contains a value named name, but person.name still invokes the property. The data descriptor is checked first.

Interview rule: A data descriptor takes priority over an entry with the same name in the instance dictionary.

5. The instance dictionary comes next

If lookup finds no data descriptor with the requested name, Python checks the instance's own attributes. 

class Person:
    pass


person = Person()
person.age = 30

print(person.age)          # 30
print(person.__dict__)     # {'age': 30}

No descriptor controls age, so Python returns the value found in person.__dict__.

6. Class attributes and ordinary methods

If the instance does not supply the name, lookup can return an ordinary attribute from the class hierarchy. 

class Person:
    category = "user"

    def greet(self):
        return "Hello"


person = Person()

print(person.category)  # user
print(person.greet)     # <bound method Person.greet ...>

The string category is returned directly. The function greet behaves differently because functions implement __get__, making them non-data descriptors. Access through the instance creates a bound method.

Functions stored in classes are non-data descriptors. Their descriptor behavior is what binds an instance to an ordinary instance method.

7. Parent classes and the MRO

A class-level search follows the class's method resolution order. The MRO tells Python which class to inspect first, then next. 

class A:
    x = 10


class B(A):
    pass


b = B()

print(B.__mro__)
print(b.x)  # 10

Python does not find x on the instance or on B, so the class-hierarchy search continues to A and returns 10.

8. __getattr__ is the last chance

class Person:
    def __getattr__(self, name):
        return "Not found"


person = Person()
print(person.salary)  # Not found

No earlier lookup stage can provide salary, so Python invokes __getattr__. Existing attributes do not use this fallback.

A production implementation should often raise AttributeError for names it cannot handle. Returning a value for every missing name can hide spelling mistakes. 

class Person:
    def __getattr__(self, name):
        if name == "display_name":
            return "Anonymous"

        raise AttributeError(
            f"{type(self).__name__!s} has no attribute {name!r}"
        )

9. Data versus non-data descriptors

The essential difference is their priority relative to the instance dictionary.

  • A non-data descriptor defines __get__ but not __set__ or __delete__. An instance attribute can shadow it.
  • A data descriptor defines __set__ or __delete__ and usually __get__. It takes priority over the instance dictionary.

Normal method: a non-data descriptor

class Person:
    def greet(self):
        return "Hello"


person = Person()
print(person.greet())  # Hello

person.greet = "Overwritten"
print(person.greet)    # Overwritten

An ordinary function supplies __get__ but not __set__. After the assignment, the instance dictionary contains greet. Instance lookup wins over the non-data descriptor on the class. 

print(person.__dict__)
# {'greet': 'Overwritten'}

Property: a data descriptor

class Person:
    @property
    def greet(self):
        return "Hello"


person = Person()
print(person.greet)  # Hello

person.greet = "Overwritten"
# AttributeError: property 'greet' of 'Person' object has no setter

The property routes the assignment through its descriptor logic. Because no setter exists, it raises AttributeError instead of adding greet to the instance dictionary.

Final comparison: An instance attribute can shadow an ordinary method. A property remains in control because it is a data descriptor.

Summary

  • __getattribute__ drives normal instance attribute access.
  • Data descriptors take priority over instance attributes.
  • Instance attributes take priority over non-data descriptors and ordinary class attributes.
  • Class searches follow the MRO.
  • __getattr__ handles names that normal lookup cannot resolve.
Once you know the priority order, properties, bound methods, instance shadowing, and inherited attributes all follow the same lookup system.
