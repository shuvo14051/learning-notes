Object-Oriented Programming

Understanding Python Inheritance

Build the mental model behind parent classes, specialized child classes, attribute lookup, method overriding, and the MRO.

August 24, 2026 • Ahamed Learning Notes

Inheritance lets a class reuse and specialize behavior from another class. Once you understand that Python searches a class hierarchy rather than copying everything into each child, inheritance becomes predictable.

This foundation prepares you for method overriding, super(), abstract base classes, and multiple inheritance.

01 — Relationship

The core idea: an “is-a” relationship

Inheritance commonly represents specialization. A child class is a more specific form of its parent class. 

Animal
  ↓
 Dog
  ↓
Puppy

This hierarchy says:

  • a Dog is an Animal
  • a Puppy is a Dog
  • therefore, a Puppy is also an Animal

Each level can add more specialized behavior while retaining access to behavior defined higher in the hierarchy. 

Animal: eat(), sleep()
   ↓
Dog:    bark()
   ↓
Puppy:  play()

A Puppy can use eat(), sleep(), bark(), and play() because attribute lookup can continue through its ancestor classes.

Use inheritance when the child can genuinely stand in for the parent. If the relationship is only “has-a” or “uses-a,” composition may be a better design.

02 — Syntax

Define a child class

Place the parent class inside parentheses:

class Animal:
    def eat(self):
        return "eating"


class Dog(Animal):
    def bark(self):
        return "barking"


dog = Dog()

print(dog.eat())
print(dog.bark())
eating
barking

Dog defines bark itself. It does not define eat, so Python finds eat through Animal.

03 — Reused definitions

What a child class can access

A child class can normally use definitions from its ancestors:

  • ordinary methods
  • class attributes
  • properties and other descriptors
  • class methods
  • static methods
class Animal:
    species = "animal"

    def eat(self):
        return "eating"

    @property
    def status(self):
        return "awake"

    @classmethod
    def category(cls):
        return "living thing"

    @staticmethod
    def has_cells():
        return True


class Dog(Animal):
    pass


dog = Dog()

print(dog.eat())
print(dog.status)
print(Dog.species)
print(Dog.category())
print(Dog.has_cells())

These definitions are not copied into Dog.__dict__. Python finds them by searching the class hierarchy. 

print("eat" in Dog.__dict__)     # False
print("eat" in Animal.__dict__)  # True
“Inherited” usually means “available through lookup,” not “duplicated inside the child class.”

04 — Lookup

The attribute lookup chain

Consider an ordinary attribute access:

dog.sound

A useful simplified path is:

dog instance
     ↓
Dog class
     ↓
Animal class
     ↓
object

Python first accounts for descriptor priority, then instance storage, and then searches the class hierarchy according to the method resolution order. The search stops when the applicable attribute is found. 

class Animal:
    sound = "some sound"


class Dog(Animal):
    pass


dog = Dog()
print(dog.sound)  # some sound

For this simple class attribute, Python checks:

  1. dog has no instance attribute named sound.
  2. Dog does not define sound.
  3. Animal defines it, so lookup returns that value.

05 — Specialization

A child can override a parent definition

If a child class defines the same name as its parent, lookup finds the child's definition first. 

class Animal:
    def speak(self):
        return "generic sound"


class Dog(Animal):
    def speak(self):
        return "bark"


print(Dog().speak())  # bark

This is method overriding. The parent method still exists on Animal; the child method is simply selected first for a Dog object.

Class attributes can also be overridden

class Animal:
    sound = "generic sound"


class Dog(Animal):
    sound = "bark"


print(Animal.sound)  # generic sound
print(Dog.sound)     # bark
Overriding changes which definition lookup selects for the child. It does not erase or modify the parent's definition.

06 — Multiple levels

A three-level hierarchy

class Animal:
    def eat(self):
        return "animal eating"


class Dog(Animal):
    def bark(self):
        return "dog barking"


class Puppy(Dog):
    def play(self):
        return "puppy playing"


puppy = Puppy()

print(puppy.eat())
print(puppy.bark())
print(puppy.play())
animal eating
dog barking
puppy playing

For class-level definitions, the search path is:

Puppy → Dog → Animal → object

play is found on Puppy, bark on Dog, and eat on Animal.

07 — Initialization

Constructor lookup follows the same hierarchy

__init__ is also found through normal method lookup. A child without its own __init__ can use the parent's. 

class Animal:
    def __init__(self, name):
        self.name = name


class Dog(Animal):
    pass


dog = Dog("Fido")
print(dog.name)  # Fido

If Dog defines its own __init__, that method overrides the inherited initializer. The child can cooperate with the parent using super(), which is the subject of the next inheritance step.

08 — Inspection

Inspect the method resolution order

Every class exposes the exact class search order through __mro__ and mro(). 

print(Puppy.__mro__)
print(Puppy.mro())
(<class '__main__.Puppy'>,
 <class '__main__.Dog'>,
 <class '__main__.Animal'>,
 <class 'object'>)

The method resolution order is not limited to methods. It is the order used to search the class hierarchy for attributes generally.

Reading ClassName.__mro__ is often the fastest way to understand which definition Python will find in an inheritance hierarchy.

09 — Relationship checks

Use isinstance() and issubclass()

puppy = Puppy()

print(isinstance(puppy, Puppy))   # True
print(isinstance(puppy, Dog))     # True
print(isinstance(puppy, Animal))  # True

print(issubclass(Puppy, Dog))     # True
print(issubclass(Puppy, Animal))  # True
print(issubclass(Dog, Puppy))     # False

These checks account for inheritance. Comparing type(puppy) is Animal would be false because the exact type is Puppy, even though the object is also an instance of every ancestor in the hierarchy.

10 — Summary

The inheritance mental model

  • Inheritance models a specialization or “is-a” relationship.
  • Ancestor definitions are reused through attribute lookup.
  • A child can add new behavior or override an inherited name.
  • Overriding does not modify the parent's definition.
  • The MRO defines the class-hierarchy search order.
  • isinstance() and issubclass() understand the hierarchy.
Final idea: A child class does not receive a copy of everything above it. Python follows the MRO and reuses the first applicable definition it finds.
