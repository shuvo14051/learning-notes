Method Overriding in Python

Learn how child classes replace, extend, and specialize inherited behavior while preserving a common interface.

August 26, 2026 • Ahamed Learning Notes

Once inheritance makes sense, method overriding is the next essential step. Overriding lets a child class provide a more specific implementation of behavior already defined by an ancestor.

Three related ideas matter most:

  • replacement: use entirely different behavior
  • extension: reuse inherited behavior and add to it
  • specialization: preserve an interface with type-specific logic

01 — Replacement

Replace an inherited method

A child overrides a method by defining a method with the same name as an inherited method. 

class Animal:
    def speak(self):
        return "generic sound"


class Dog(Animal):
    def speak(self):
        return "bark"


print(Dog().speak())  # bark

Lookup finds speak on Dog before reaching Animal, so the child's implementation runs. 

dog instance → Dog.speak → stop

The parent method has not been deleted or modified. Animal().speak() still returns "generic sound".

Overriding changes which implementation lookup selects for a child object. It does not overwrite the method stored on the parent.

02 — Design choice

When should a child override?

Override when a general operation applies to every type in a hierarchy, but a subtype needs its own implementation.

A shape hierarchy is a classic example:

       Shape.area()
        /    |    \
  Circle  Rectangle  Triangle

Every shape has an area, but each kind of shape uses a different formula. The shared method name creates a consistent interface; the overrides provide the specialized behavior.

A useful override should continue honoring the parent's contract: callers using the parent interface should still be able to work with the child object without unexpected requirements or results.

03 — Specialization

A shape hierarchy

The base method establishes the interface. Raising NotImplementedError makes it clear that a concrete subclass must provide the formula. 

class Shape:
    def area(self):
        raise NotImplementedError("subclasses must implement area()")

Each child supplies its own implementation:

import math


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return math.pi * self.radius**2


class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height


class Triangle(Shape):
    def __init__(self, base, height):
        self.base = base
        self.height = height

    def area(self):
        return 0.5 * self.base * self.height

All three subclasses support the same expression: shape.area(). Only the implementation changes.

04 — Polymorphism

One interface, many implementations

Because every shape provides area(), one loop can work with all of them. 

shapes = [
    Circle(3),
    Rectangle(4, 5),
    Triangle(6, 3),
]

for shape in shapes:
    print(round(shape.area(), 2))
28.27
20
9.0

Python evaluates shape.area() at runtime. The actual object's class determines which implementation is selected. This ability to use one interface with different types is polymorphism.

The loop does not need a chain of if statements to identify each shape. The objects supply the appropriate behavior.

05 — Extension

Reuse and extend inherited behavior

An override does not always need to discard the inherited method. It can call the next implementation and add more behavior. 

class Logger:
    def log(self, message):
        return f"log started: {message}"


class FileLogger(Logger):
    def log(self, message):
        parent_result = super().log(message)
        return parent_result + " -> written to file"


logger = FileLogger()
print(logger.log("user signed in"))
log started: user signed in -> written to file

Execution has two parts:

  1. super().log(message) invokes the next applicable log implementation in the MRO.
  2. The child continues and adds its file-specific result.
super() means “continue searching after the current class in the MRO.” In single inheritance that often reaches the direct parent, but the MRO definition remains correct for multiple inheritance too.

06 — Extension patterns

Add behavior before or after super()

An override can wrap inherited behavior:

class Service:
    def process(self, data):
        return data.strip()


class AuditedService(Service):
    def process(self, data):
        print("processing started")

        result = super().process(data)

        print("processing finished")
        return result


service = AuditedService()
print(service.process("  report  "))
processing started
processing finished
report

This structure is useful for logging, validation, metrics, normalization, and other steps that surround reusable base behavior.

07 — Substitutability

Keep the overriding interface compatible

Callers written for the parent should generally be able to use the child without changing how they call the method. 

class Formatter:
    def format(self, text):
        return text


class UppercaseFormatter(Formatter):
    def format(self, text):
        return text.upper()

Both versions accept text and return formatted text. The override specializes the result while preserving the contract.

A surprising override

class BrokenFormatter(Formatter):
    def format(self, text, required_prefix):
        return required_prefix + text

Code that safely calls formatter.format(text) for a Formatter will fail when given BrokenFormatter. Adding a new required argument breaks the expected interface.

A good override preserves the expectations established by the parent while changing the implementation appropriately.

08 — Common mistakes

Watch for these overriding problems

Forgetting to return the inherited result

class FileLogger(Logger):
    def log(self, message):
        super().log(message)
        # No return statement: the result is None

Calling the class directly instead of using super()

class FileLogger(Logger):
    def log(self, message):
        result = Logger.log(self, message)
        return result + " -> written to file"

This can work in simple inheritance, but it hard-codes Logger and does not cooperate with a multiple- inheritance MRO. Prefer super() for cooperative overrides.

Accidentally changing the method name

class Dog(Animal):
    def speaks(self):
        return "bark"

speaks is a new method, not an override of speak. Python does not use an @override keyword to catch this automatically at runtime, though type checkers can help detect mistakes.

09 — Mental model

Interface above, implementation below

        Shape.area()
         /    |    \
Circle.area() | Rectangle.area()
              |
        Triangle.area()

The parent establishes the shared operation. Each concrete child supplies behavior appropriate to its own state. Callers depend on the stable interface instead of the formula inside each class.

10 — Summary

Key takeaways

  • A child overrides a method by defining the same method name.
  • Lookup selects the first applicable definition in the MRO.
  • An override can fully replace or extend inherited behavior.
  • super() continues lookup through the MRO.
  • A shared interface enables polymorphic code.
  • Overrides should preserve the parent's usable contract.
Final idea: Overriding lets specialized objects answer the same request in different, type-appropriate ways.
