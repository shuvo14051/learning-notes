Object-Oriented Programming

Instance, Class, and Static Methods in Python

Understand what Python binds to each method type, which state it can access naturally, and when each one is the right design choice.

August 29, 2026 • Ahamed Learning Notes

The difference between instance, class, and static methods is mainly about automatic binding. Python can automatically provide an instance, provide a class, or provide nothing at all.

Method type Receives automatically Typical purpose
Instance method self: an instance Read or change one object's state
Class method cls: a class Work with class state or alternative constructors
Static method Nothing Related utility logic

01 — Instance methods

Work with a specific object

An instance method is a function that becomes bound to an object during attribute access. Python passes that object as the first argument, conventionally named self. 

class User:
    platform = "AI App"

    def __init__(self, name):
        self.name = name

    def show_info(self):
        return f"{self.name} uses {self.platform}"


user = User("Ahamed")
print(user.show_info())
Ahamed uses AI App

When user.show_info() runs:

  1. The method is bound to user.
  2. Python passes user as self.
  3. self.name is found on the instance.
  4. self.platform is not on the instance, so lookup finds it on User.
An instance method can naturally access instance state through self. It can also read class attributes through the normal attribute lookup process.

Assigning through self can create a shadow

class User:
    platform = "AI App"

    def __init__(self, name):
        self.name = name

    def change_platform(self):
        self.platform = "ML App"


user_1 = User("Ahamed")
user_2 = User("John")

user_1.change_platform()

print(user_1.platform)  # ML App
print(user_2.platform)  # AI App
print(User.platform)    # AI App

The assignment creates platform on user_1. It shadows the class attribute for that one instance; it does not update User.platform.

Changing class state from an instance method

An instance method can reach its instance's class explicitly: 

class User:
    platform = "AI App"

    def change_platform(self):
        type(self).platform = "ML App"


user_1 = User()
user_2 = User()
user_1.change_platform()

print(user_1.platform)  # ML App
print(user_2.platform)  # ML App
print(User.platform)    # ML App

This updates the class of self. When changing shared class state is the method's main responsibility, a class method usually communicates that intention more clearly.

Calling through the class requires an instance

class User:
    def show(self):
        return "Hello"


User.show()
# TypeError: User.show() missing 1 required positional argument: 'self'

Access through the class does not bind a particular instance. You can supply one manually with User.show(user), or use the normal bound call user.show().

02 — Class methods

Work with the calling class

A class method is declared with @classmethod. Python binds it to a class and supplies that class as the first argument, conventionally named cls. 

class AppConfig:
    theme = "light"
    version = "1.0"

    def __init__(self, app_name):
        self.app_name = app_name

    @classmethod
    def set_theme(cls, new_theme):
        cls.theme = new_theme

    @classmethod
    def describe(cls):
        return f"theme={cls.theme}, version={cls.version}"


dashboard = AppConfig("Dashboard")
analytics = AppConfig("Analytics")

print(AppConfig.describe())
AppConfig.set_theme("dark")
print(AppConfig.describe())
print(dashboard.theme, analytics.theme)
theme=light, version=1.0
theme=dark, version=1.0
dark dark

A class method can be accessed through the class or an instance. In either case, cls refers to the class used for the binding—not to a particular instance.

A class method has no specific instance

class AppConfig:
    def __init__(self, app_name):
        self.app_name = app_name

    @classmethod
    def wrong(cls):
        return cls.app_name


AppConfig.wrong()
# AttributeError: type object 'AppConfig' has no attribute 'app_name'

app_name exists separately on each instance. The class method receives only the class, so it does not know which instance's app_name should be used.

Class methods as alternative constructors

A common class-method use is an alternative constructor: a method that converts another representation into the arguments needed to build an object. 

class User:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_string(cls, data):
        name, age = data.split(",")
        return cls(name.strip(), int(age))


user = User.from_string("Ahamed, 30")

print(user.name, user.age)
print(user.__dict__)
Ahamed 30
{'name': 'Ahamed', 'age': 30}

The parsing logic stays next to the class, while cls(...) performs the actual construction.

Why cls matters for inheritance

class Admin(User):
    pass


admin = Admin.from_string("John, 40")
print(type(admin))
<class '__main__.Admin'>

Accessing from_string through Admin binds cls to Admin. Therefore, return cls(...) creates an Admin rather than always creating a User.

Prefer cls(...) inside alternative constructors. It preserves subclass behavior and avoids hard-coding the base class.

03 — Static methods

Keep related utility logic in the class namespace

A static method is declared with @staticmethod. It receives no instance or class automatically. Its arguments behave like the arguments of a regular function. 

class MathUtils:
    @staticmethod
    def add(x, y):
        return x + y


print(MathUtils.add(3, 4))  # 7

Use a static method when a function conceptually belongs with a class but does not need instance state or dynamic class access.

There is no automatic self

class User:
    def __init__(self, name):
        self.name = name

    @staticmethod
    def wrong():
        return self.name


User.wrong()
# NameError: name 'self' is not defined

No variable named self exists unless it is explicitly declared and supplied as an argument.

Class access must be explicit

class User:
    platform = "AI App"

    @staticmethod
    def show_platform():
        return User.platform


print(User.show_platform())  # AI App

This works because the function names User directly. It is less flexible under inheritance than using cls.platform in a class method.

04 — Choosing a method

Ask what the operation needs

If the operation needs... Choose... Reason
One object's state Instance method It receives self
Dynamic class state or construction Class method It receives cls
Neither instance nor class state Static method It receives nothing automatically
Start with the data the operation requires. The correct binding choice usually follows naturally from that requirement.

05 — Put it together

Complete example

class User:
    platform = "AI App"

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def describe(self):
        return f"{self.name}, age {self.age}, uses {self.platform}"

    @classmethod
    def from_string(cls, data):
        name, age = data.split(",")
        return cls(name.strip(), int(age))

    @classmethod
    def set_platform(cls, platform):
        cls.platform = platform

    @staticmethod
    def is_valid_age(age):
        return isinstance(age, int) and age >= 0


user = User.from_string("Ahamed, 30")

print(user.describe())
print(User.is_valid_age(user.age))

User.set_platform("ML App")
print(user.describe())
Ahamed, age 30, uses AI App
True
Ahamed, age 30, uses ML App
Summary: Instance methods receive an object, class methods receive the calling class, and static methods receive no automatic first argument.
