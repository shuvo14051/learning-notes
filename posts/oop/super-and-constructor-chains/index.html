Object-Oriented Programming

super() and Constructor Chains in Python

Follow object initialization through a hierarchy and learn how cooperative methods pass control and arguments along the MRO.

August 28, 2026 • Ahamed Learning Notes

After inheritance and method overriding, the next step is understanding how several classes cooperate to build one object. Each class can initialize the state it owns and use super() to continue the initialization chain.

super() does not simply mean “my parent.” It creates a proxy that continues method lookup after the current class in the method resolution order.

01 — Layered initialization

Connect constructors with super()

Consider this three-level hierarchy:

Vehicle → Car → ElectricCar
class Vehicle:
    def __init__(self, brand):
        self.brand = brand

    def describe(self):
        return f"Vehicle brand: {self.brand}"


class Car(Vehicle):
    def __init__(self, brand, doors):
        super().__init__(brand)
        self.doors = doors

    def describe(self):
        return f"{super().describe()}, doors: {self.doors}"


class ElectricCar(Car):
    def __init__(self, brand, doors, battery):
        super().__init__(brand, doors)
        self.battery = battery

    def describe(self):
        return f"{super().describe()}, battery: {self.battery}"


car = ElectricCar("Tesla", 4, "100 kWh")

print(car.brand)
print(car.doors)
print(car.battery)
print(car.describe())
Tesla
4
100 kWh
Vehicle brand: Tesla, doors: 4, battery: 100 kWh

Each class initializes the state it is responsible for:

  • Vehicle initializes brand.
  • Car adds doors.
  • ElectricCar adds battery.

There is only one ElectricCar object. Each constructor receives the same instance as self and adds state to it.

02 — Call stack

Follow the exact constructor flow

class Vehicle:
    def __init__(self):
        print("Vehicle constructor")


class Car(Vehicle):
    def __init__(self):
        print("Car constructor start")
        super().__init__()
        print("Car constructor end")


class ElectricCar(Car):
    def __init__(self):
        print("ElectricCar constructor start")
        super().__init__()
        print("ElectricCar constructor end")


ElectricCar()
ElectricCar constructor start
Car constructor start
Vehicle constructor
Car constructor end
ElectricCar constructor end

The calls move down the MRO:

ElectricCar.__init__()
          ↓
     Car.__init__()
          ↓
   Vehicle.__init__()

When the final called method returns, suspended execution resumes in reverse order—first inside Car, then inside ElectricCar.

03 — Broken chain

What happens when super() is omitted?

class Vehicle:
    def __init__(self):
        self.brand = "Unknown"


class Car(Vehicle):
    def __init__(self):
        self.doors = 4


car = Car()

print(car.doors)  # 4
print(car.brand)  # AttributeError

Car.__init__ overrides the inherited initializer. It never continues to Vehicle.__init__, so brand is never assigned.

Python does not automatically run every constructor in the hierarchy. Cooperative classes must explicitly continue the chain.

04 — Direct parent calls

Why not call the parent class by name?

class Car(Vehicle):
    def __init__(self, brand, doors):
        Vehicle.__init__(self, brand)
        self.doors = doors

This can work in a simple hierarchy, but it hard-codes Vehicle. It bypasses cooperative MRO behavior and can call a class twice—or skip another class—when multiple inheritance is introduced. 

class Car(Vehicle):
    def __init__(self, brand, doors):
        super().__init__(brand)
        self.doors = doors

The super() version asks Python to select the next applicable implementation according to the current class and the actual object's MRO.

05 — Argument flow

Pass arguments through the chain

class Person:
    def __init__(self, name):
        self.name = name


class Employee(Person):
    def __init__(self, name, salary):
        super().__init__(name)
        self.salary = salary


class Manager(Employee):
    def __init__(self, name, salary, department):
        super().__init__(name, salary)
        self.department = department


manager = Manager("Alice", 90_000, "Engineering")

print(manager.name)
print(manager.salary)
print(manager.department)
Alice
90000
Engineering

Each constructor accepts the information needed at its level and forwards the remaining parent arguments in the expected form. 

Manager instance
├── name        ← Person
├── salary      ← Employee
└── department  ← Manager

06 — Resolution order

The MRO controls super()

class A:
    pass


class B(A):
    pass


class C(B):
    pass


print(C.__mro__)
(<class '__main__.C'>,
 <class '__main__.B'>,
 <class '__main__.A'>,
 <class 'object'>)

The class lookup order is:

C → B → A → object

Inside a method defined on C, zero-argument super() starts after C in this order. Inside a method defined on B, it starts after B.

The MRO is shared by ordinary inherited lookup and cooperative super() calls, but super() begins after a particular class rather than restarting at the instance.

07 — Beyond constructors

super() works with other methods

class Logger:
    def log(self, message):
        return f"Log start: {message}"


class FileLogger(Logger):
    def log(self, message):
        parent_result = super().log(message)
        return parent_result + " -> writing to file"


logger = FileLogger()
print(logger.log("saved"))
Log start: saved -> writing to file

The same mechanism that connects constructors can extend any compatible inherited method.

08 — Flexible arguments

Build a cooperative chain with **kwargs

In more flexible hierarchies, each class can consume its own keyword-only argument and forward the unused arguments. 

class A:
    def __init__(self, *, a=None, **kwargs):
        self.a = a
        super().__init__(**kwargs)


class B(A):
    def __init__(self, *, b=None, **kwargs):
        self.b = b
        super().__init__(**kwargs)


class C(B):
    def __init__(self, *, c=None, **kwargs):
        self.c = c
        super().__init__(**kwargs)


item = C(a=1, b=2, c=3)

print(item.a)
print(item.b)
print(item.c)
1
2
3

The argument flow is:

C consumes c; forwards a, b
             ↓
B consumes b; forwards a
             ↓
A consumes a; forwards nothing
             ↓
object.__init__()

Parameters such as c, b, and a are removed from kwargs by Python's argument binding before the method body runs. Only unconsumed keywords continue to the next method.

Do not read values with kwargs.get() and then forward the unchanged dictionary all the way to object. object.__init__() does not accept leftover keyword arguments.

09 — End of the chain

Why the base class still calls super()

Every ordinary Python class ultimately derives from object. 

class A:
    pass


print(A.__mro__)
# (<class '__main__.A'>, <class 'object'>)

In the cooperative example, A may look like the final custom class, but it may not always be last when another class is added through multiple inheritance. Calling super() lets the MRO decide what comes next.

When no other implementation remains, the call reaches object.__init__(). At that point every custom keyword must have been consumed.

10 — Cooperation rules

Design methods that can form a chain

Cooperative initialization works when participating classes agree:

  • each implementation calls super() exactly once
  • each class handles only the state it owns
  • method signatures accept and forward compatible arguments
  • unknown keyword arguments are forwarded rather than discarded
  • all custom arguments are consumed before reaching object

If one class omits super(), calls a base class directly, or forwards incompatible arguments, it can break every class that comes later in the MRO.

11 — Summary

Key takeaways

  • Python does not run all constructors automatically.
  • super() continues lookup through the MRO.
  • Each constructor can initialize one layer of the same object.
  • Direct base-class calls do not cooperate with the MRO.
  • Explicit parameters are clearest for simple hierarchies.
  • **kwargs can support cooperative, flexible chains.
Final idea: Cooperative inheritance works when every class completes its responsibility and deliberately passes control to the next class in the MRO.
